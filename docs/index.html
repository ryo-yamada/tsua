Introduction

Repository: github.com/ryo-yamada/tsua

Tsua is a tiny, minimalistic HTTP server framework built on top of LuaSocket.

The framework allows you to simply serve files and send data over HTTP for something like a website, such as a portfolio, without messing with raw, low-level HTTP too much. It works similar to Express.js or Python's Flask.

Because Lua's runtime is pretty small compared to something like Python's Flask, tsua runs well on stuff like old devices, a tiny VPS, or a Raspberry Pi Zero W.

Currently, tsua is experimental and only encouraged for static websites where dynamic activity is limited. Security hardening is something I want to gladly work towards. When deploying publicly with tsua, it is recommended that you run it in a containerized environment like Docker.

Fun fact: this site is hosted with tsua!

Minimal Application

This is what a minimal webserver with tsua could look like:

local Tsua = require("tsua") -- 1
local app = Tsua.new() -- 2

app:get("/", function(req, res) -- 3
    res:serve("./index.html") -- 4
end)

app:listen(19999) -- 5

Well, what does this code do?

  1. First, we require the tsua module file
  2. Then, we initialize a server instance to access tsua's functionality
  3. After that, we can compose a route (in this case, root) that takes GET requests
  4. This route then serves an index.html file that the client browser can display every time a GET request is made
  5. Finally, we set up the server to listen on a port, in this case port 19999.

You can then save this file as something like server.lua, and run it with lua server.lua. Make sure lua and luarocks is installed, and that luasocket is installed through luarocks aswell.

Static Files

Most web apps use static files for serving CSS, JS, images, etc. It's a way to serve files directly to the client without needing any specific route handling. Tsua makes it pretty simple. Create a directory called static, and place your desired files in it, for example, a style.css file.

In tsua, it would then be utilized and exposed like so:

app:static("/static", "./static")

And that's it! Tsua will now serve any static file(s) per usual, such as /static/style.css

The first argument is the URL prefix, and the second one is the directory's name on disk.

Just so you know, static directories are always checked before route handlers. If a path matches a registered static directory, the static file gets served, and the route handler will not be executed.

And as a side note, the directory name doesn't NEED to be static specifically. You could do something like app:static("/assets", "./public"), no problem.

Contributing

Contribution is heavily encouraged, and I'm trying to keep tsua small and approachable for this reason

If you are:

  • learning lua
  • interested in HTTP
  • looking for something to contribute to

then I'm looking forward to working with you.

Issues, pull requests, feature suggestions, and discussion are all appreciated. If you're looking to contribute but aren't sure how, you can check the issue tracker, in which I or others might post some issues for you to look into.

Development is currently focused on:

  • Core functionality
  • Developer experience enhancements

Philosophy

This was a project I started just for fun, as I wanted to see how easy it would be to deliver a site over the web with a Lua backend. However, it started becoming its own little framework, and so I decided to publish it on GitHub. My plan is to continue developing it with a focus on simplicity.

This framework is aimed towards sites that don't have too much dynamic functionality. Portfolios, documentation, etc. However, I suppose when this framework continues development, it will probably be able to support more dynamic functionality.

Security Policy

If you think you've found a vulnerability for tsua, please reach out to me at f@placeq.com, and we'll continue speaking there.

When sending me an email, please provide details in the following structure:

  • Description of the issue
  • How to reproduce
  • Potential impact
  • Suggested fix, if available

Please do not publicly report or discuss security vulnerabilities.
